# 到位／完成条件的直接后继

## 适用范围
用户要求统一 `S=k → S=k AND F` 这类采集边界时加载；F可以是一个或多个正向BOOL条件。
可应用于预测阶段已有候选/工艺草表，也可在独立评价时解释GT。预测阶段绝不读取GT。
变量名、轴号、工位、步号、固定步长都不是规则；PosOK/Done/到位的文字也不能单独证明关系。

## 计算方式
1. 保持开始标签不变。确认结束式包含同一状态锚点和正向反馈条件。
2. 在同一变量作用域内查该状态的真实直接写入目标。仅使用完整可解释的源码门控，不使用相邻步号推测或同网络共现。
3. 在当前状态成立时，迁移门控必须蕴含原结束式中的所有反馈条件。OR旁路允许不反馈就跳转的，不纳入该反馈的替代路径。
4. 输出 `S=k → S=j`。j可以小于k，也可以为0或1；这不自动意味着它是异常复位。
5. 不跨过j再找更远的汇合状态。同一反馈对应多个直接目标时分别记录分支，不任取一条，不把多条诊断当单条GT严格命中。
6. 保留完整门控、额外门控、源作用域、迁移证据ID和原始反馈表达式。定时器、其他轴反馈、握手等不能默默删掉。
7. 缺图、未知功能块输出、动态目标、作用域冲突、跨状态复合、内部自环或不支持的表达式，保留review和原池，不猜后继。

示意：源程序有 `S=70 AND F AND Run → S:=4`，则非复合候选可用 `S=70 → S=4`；仍需注明Run门控。
绝不是 `S=70 → S=80`，也不是无条件认定 `S=70 AND F` 与 `S=4` 同时为真。

## 计时语义
这是“在指定正常执行门控下，用状态进入事件替代反馈边界”的采集口径。
反馈原式在状态写入前成立，目标状态在写入后成立；不是布尔等价。
额外门控若未成立，可能把反馈到位之后的等待计入时间；若有定时器，还可能加入稳定时间。
状态可能在同一扫描再次改写，外部采样也可能漏掉瞬态；程序静态解析没有证明时不声称时间戳相等。
须按当前动作循环锁存起点，终点在起点之后、同一循环生效；复位/取消/跳步需另外排除。

## 程序接口
`feedback_successor.py` 是共享只读解析器。`AtomicProjector` 在预测和评价分别调用。
主采集表仍为 `prediction_collection_pairs.csv`，完整原始对仍在 `prediction_candidate_pairs.csv`。
实际含反馈终点的候选会记录到 `prediction_feedback_successor_audit.csv`；若此表为空，只表示本次候选本来已经是状态对等其他形式，不代表未发现动作。
完整条件留在 `prediction_atomic_conditions.json`，不能只交两个标签而隐藏限制。

可单条查询（只读，不增改预测）：
`python feedback_successor.py --graph "run/source_transition_graph.json" --start "Cell.Phase=70" --end "Cell.Phase=70 AND Motor.InPlace" --out "review/feedback.json"`

## 评价
- 只查已有的一条完整预测；不能看到GT后生成预测或跨行拼接。
- 同一对已经完全匹配的，仍按原标签形式口径计分。
- 本规则找到局部直接后继时，标记“有条件的迁移替代”，展示预测行号、原终点、替代终点及附加门控；不计严格布尔/时间等价分子。
- 不把“可以采用的工艺采集边界”混写为“已证明的反馈时刻”。不为提高分数移除复位/未知写入阻断项。
- 不要求候选数增加：正确状态对若原本已存在，本次改善是解释和匹配诊断，不是新找到了动作。
